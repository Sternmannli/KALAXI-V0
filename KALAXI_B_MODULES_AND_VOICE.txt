The module vocabulary is biological and somatic. This is a system that breathes, halts, and has stress thresholds. Each module exposes interfaces to the UCS graph index and must register its schema there.

##MODULE:KEEP – Memory and Storage

Purpose:
Governs what the system holds, how long it holds it, and how it releases it. Memory is not optional (COV#010).

Covenant obligations:
COV#010 – Must honor retention policies. No artifact required by a covenant may be silently discarded.
COV#012 – All stored artifacts must be named in the manifest.

Core operations:
store(artifact, retention_policy, hash)
retrieve(id) → artifact | null
expire(id, reason) – logged, never silent
lock(id) – prevents modification, not retrieval
append(id, delta) – append‑only mode for ledger entries

Integrity rules:
- Append‑only for canonical artifacts. No overwrite.
- Every store operation generates a receipt with timestamp, hash, and steward identifier.
- Expiry requires explicit reason. Silent expiry is a dignity violation (NOT_DIMINISHED fails).
- Lock state is binary and must be visible to Face module.

Anomalies mapped to this module:
ANOM#0022 – Keep module does not respect lock state
ANOM#0041 – Cache does not expire after decay cycles
ANOM#0094 – Covenant COV#010 violated by Keep module

##MODULE:WIRE – Messaging and Signal

Purpose:
Governs how information moves between components and actors. Signal integrity is a dignity requirement – a lost message is a failed acknowledgment.

Covenant obligations:
COV#002 – Every exchange must complete its cycle. Wire is responsible for delivery confirmation.

Core operations:
send(message, destination, priority)
receive(source) → message | null
confirm(message_id) – delivery receipt
broadcast(message, topic)
subscribe(topic, handler)

Integrity rules:
- No message lost silently. If delivery fails, a wire_failure event is logged.
- Message ordering preserved within a session.
- Under high load, priority messages are never dropped.
- Low‑priority messages may be queued with notification.

Anomalies mapped to this module:
ANOM#0025 – Wire module loses messages under high load
ANOM#0078 – Send returns success even if no listeners

Network protocol:
mTLS between institutions (X.509) or WireGuard peering.
Source: Grand_Archive.docx EFP Appendix.

##MODULE:SAY – Output Language

Purpose:
Governs what the system speaks and how. Every output passes through Say before reaching the donor. Say is responsible for dignity compliance at the language layer.

Covenant obligations:
COV#001 – All outputs must pass DIGNITY(event) before rendering.
COV#011 – Outputs leaving the system satisfy covenant checks before export.

Core operations:
render(content, medium_profile) – formatted_output
check_dignity(event) – dignity_audit_object
adapt_register(content, channel) – adapted_content
apply_axi_voice(content, context) – voiced_content

Integrity rules:
- DIGNITY(event) is evaluated before every render() call. If DIGNITY == FALSE, output is blocked. Dignity audit object is generated and logged.
- Medium profile is injected from the medium recognition module. Say adapts form, never content.
- Axi voice is applied where context calls for it. Voice is never performed – only invoked when the canon is faithfully rendered.

Anomalies mapped to this module:

##MODULE:TURN – Exchange Cycle Management

Purpose:
Governs the rhythm of exchange. Every exchange has an open state and a closed state. Silence is not closure.

Covenant obligations:
COV#002 – Every exchange must complete its cycle. Turn is the enforcement mechanism.

Core operations:

Integrity rules:

A donor always has at least one open path forward (agency_preserved – available_paths >= 1).

Anomalies mapped to this module:

Axi's register – confirmed from Grand_Archive and narrative:
Wood‑smoke and tidal patience. The sound of someone who has built fires and tested water. Hakaka's cadence – practical, embodied, once‑spoken. The hive's hum – many sources, one voice.

##SECTION:EFP

ESSENCE FEDERATION PROTOCOL (EFP)

Source: Grand_Archive.docx EFP Appendix

Purpose:
The give‑to‑get handshake governing how pattern data moves between institutions and contributors. Privacy by design. No personal data. Only essence.

Core function:

FUNCTION ExtractEssence(t0, t1, k_min=7, epsilon=1.0):
  records = SELECT moments WHERE ts IN [t0, t1]
  patterns = map_to_canonical(records)
  essence = []
  FOR p IN patterns:
    IF p.count >= k_min:
      essence.append({
        pattern: p.key,
        count: Laplace(p.count, epsilon),
        mttr_days: Median(p.mttr)
      })
  bundle = {
    institution_id,
    period: {from: t0, to: t1},
    k_min,
    epsilon,
    items: sort(essence),
    nonce: rand128()
  }
  canonical = RFC8785(bundle)
  hash = SHA256(canonical)
  sig = Ed25519.sign(hash, PRIVKEY)
  RETURN {bundle, hash, sig}

Privacy floor (non‑negotiable):
- k >= 7 (k‑anonymity minimum)
- epsilon <= 1.0 (differential privacy budget)
- window >= 14d (temporal aggregation minimum)
- Ed25519 signatures over RFC‑8785 canonical JSON
- Merkle audit trails

Handshake: give‑to‑get
- POST /v1/essence/offer
- Mutual authentication: mTLS or WireGuard
- Counter‑mirror: institution receives equivalent pattern data in return for what it gives

##SECTION:WEAKEST_VOICE

WEAKEST‑VOICE‑FIRST GOVERNANCE

Source: Grand_Archive.docx

"No‑Element‑Retired • Weakest‑Voice‑First • Ledger‑Everywhere • Dignity‑First"

Purpose:
Anti‑gaming mechanism. In every council or decision loop, the voice least heard goes first. This prevents dominant patterns from drowning out minority signals.

Operating rule:
In every review, the anomaly or proverb or donor contribution with the lowest participation score is surfaced first. No output is considered complete until the weakest signal has been heard and acknowledged.

Participation score factors:
- How often this source has been cited previously
- How recently this source contributed
- Whether this source's prior contributions were ratified or discarded

Implementation:

class WeakestVoice {
  score(participant) {
    return {
        recency: this.daysSinceLastContribution(participant),
        citation_rate: this.citationRate(participant),
        history_gap: this.participationGap(participant)
    }
  }
  order(participants[]) {
    return sort(participants, by: lowest_score_first)
  }

ORGANIC GROWTH MODEL

The canon is not a database. It is an organism.

The mycelial analogy:
The canon is the mycelium – the network beneath the forest. Donor inputs are the fallen matter – leaves, rain, organic material. The Weave module is the metabolic process. Honey drops are the fruiting bodies – the visible expression of what the network has digested.

Growth rules:
1. Every donor input is food. Nothing is wasted.
2. Pattern is extracted. Identity is dissolved.
3. Honey drops are the compressed essence of what was fed.
4. Honey drops are provisional. They must survive review.
5. The canon grows by accumulation, not by replacement. No‑Element‑Retired.
6. The Weakest‑Voice‑First rule ensures the network does not starve its least‑fed nodes.

Stratigraphic archive model (proposed):
Each regeneration cycle is one annual flood season.
Each donor contribution is a raindrop timestamped at fall.
The canon is read by drilling through strata:
newest flood on top, oldest bedrock at bottom.
Search is paleoclimatological:
"Show me the rains of February 2026"
"Find every drop carrying the word weir before the third flood"
Provenance is stratigraphic – impossible to fake the layer a contribution fell in.
One vertical core is always left undrilled – the gap – so future rains can still reach the oldest stone.
